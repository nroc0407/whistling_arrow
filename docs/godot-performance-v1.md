# Godot 성능 최적화 v1 기록

- 기록일: 2026-07-25 (Asia/Seoul)
- 엔진: Godot `4.7.1.stable.official.a13da4feb`
- 대상: 3D 기본 장면의 실시간 피치 분석과 절차적 렌더링

## 확인된 병목

최초 피치 분석은 48kHz 입력의 2,048개 샘플에 정규화 자기상관을 적용했습니다. 한 프레임에서 누적된 창을 최대 4개까지 처리했으며 모든 계산이 메인 스레드에서 실행됐습니다.

로컬 헤드리스 벤치마크에서 분석 1회는 평균 `34.556ms`, 4회 연속 처리는 약 `138.222ms`로 측정됐습니다. 이는 60fps 프레임 예산인 약 `16.667ms`를 분석 1회만으로 초과하는 수치입니다.

3D 장면에서는 바닥 격자 32개와 화살 잔상 22개가 각각 별도 `MeshInstance3D`였고, 과녁마다 `OmniLight3D`가 존재했습니다. 발광 위주의 미술 구성에 비해 draw call, 조명과 그림자 비용이 과도했습니다.

## 피치 분석 개선

- 캡처 입력을 16kHz 상당으로 선형 리샘플링합니다.
- 분석 창을 2,048개에서 1,024개 샘플로 축소했습니다.
- 누적된 모든 창 대신 가장 최신의 완전한 창 하나만 유지합니다.
- 순수 자기상관 분석은 `WorkerThreadPool` 작업으로 실행합니다.
- 리샘플링, 완료된 작업 회수, 명령 상태와 신호 갱신만 메인 스레드에서 수행합니다.
- 작업 세대 번호로 중지·재시작 전의 오래된 결과를 폐기합니다.
- 모든 WorkerThreadPool 작업은 완료 확인 뒤 `wait_for_task_completion()`으로 회수합니다.

Godot 4.7의 WorkerThreadPool 작업 회수 규칙과 장면 트리의 스레드 안전성 제한을 따랐습니다.

- <https://docs.godotengine.org/en/4.7/classes/class_workerthreadpool.html>
- <https://docs.godotengine.org/en/4.7/tutorials/performance/thread_safe_apis.html>

## 3D 렌더링 개선

- 격자 32개를 하나의 `ImmediateMesh` 선 표면으로 통합했습니다.
- 잔상 22개를 하나의 `MultiMeshInstance3D`로 통합했습니다.
- 과녁별 `OmniLight3D` 3개를 제거하고 발광 재질로 표현을 유지했습니다.
- 절차적 격자, 잔상, 락온, 홈과 과녁의 그림자 생성을 껐습니다.
- 주 방향광의 실시간 그림자를 껐습니다.
- Web export에 스레드 지원과 제한된 워커 풀 크기를 설정했습니다.

## 측정 결과

| 항목 | 변경 전 | 변경 후 |
| --- | ---: | ---: |
| 자기상관 분석 1회 | `34.556ms` | `6.339ms` |
| 메인 스레드 리샘플링 | 해당 없음 | `0.195ms` |
| 한 프레임 분석 창 상한 | 4개 | 최신 1개 |
| 분석 실행 위치 | 메인 스레드 | WorkerThreadPool |
| 바닥 격자 렌더 인스턴스 | 32개 | 1개 |
| 화살 잔상 렌더 인스턴스 | 22개 | 1개 |
| 과녁별 동적 OmniLight | 3개 | 0개 |

분석 본체의 실행 시간은 약 81.7% 감소했으며, 변경 후 `6.339ms` 분석은 워커에서 실행됩니다. 메인 스레드에 남는 정기적인 입력 전처리는 측정상 약 `0.195ms`입니다.

이 수치는 같은 PC의 Godot 4.7.1 헤드리스 실행에서 얻은 비교값이며 실제 FPS를 보장하는 절대 성능 지표는 아닙니다. 실제 GPU, 오디오 장치와 WebAssembly 환경은 별도 프로파일링이 필요합니다.
